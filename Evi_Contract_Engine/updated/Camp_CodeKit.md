# Camp CodeKit — Frontend from a jobId

Build a complete frontend for a deployed smart contract using only a `jobId`. Camp CodeKit provides a typed client, React hooks, and optional UI components to stream job progress, fetch artifacts (ABIs/sources), read audit & compliance reports, and verify contracts.

## 🚀 Quickstart

Option A — Scaffold an example app (recommended):

```bash
npm create camp-app@latest
```

Option B — Install into an existing React app:

```bash
pnpm add @tanstack/react-query @camp/codekit-core @camp/codekit-react @camp/codekit-ui
# or: npm i ...  |  yarn add ...
```

Wrap your app with React Query, set `baseUrl`, and render a Review page that takes `jobId`:

```tsx
// AppProviders.tsx
import { QueryClient, QueryClientProvider } from '@tanstack/react-query';

const qc = new QueryClient();

export function AppProviders({ children }: { children: React.ReactNode }) {
  return <QueryClientProvider client={qc}>{children}</QueryClientProvider>;
}
```

```tsx
// ReviewPage.tsx
import { useJob, useArtifacts, useAuditReport, useComplianceReport, useVerifyByJob, useVerifyStatus } from '@camp/codekit-react';
import { JobLogsPanel, ArtifactViewer, AuditReportCard, ComplianceReportCard, VerifyByJobButton, VerifyStatusBadge } from '@camp/codekit-ui';

export default function ReviewPage({ jobId }: { jobId: string }) {
  const job = useJob(jobId);
  const artifacts = useArtifacts(jobId);
  const audit = useAuditReport(jobId);
  const compliance = useComplianceReport(jobId);
  const verify = useVerifyByJob(jobId, 'basecamp');
  const status = useVerifyStatus(verify?.address, 'basecamp');

  return (
    <div>
      <h1>Review: {jobId}</h1>
      <JobLogsPanel jobId={jobId} />
      <ArtifactViewer jobId={jobId} />
      <AuditReportCard jobId={jobId} />
      <ComplianceReportCard jobId={jobId} />
      <VerifyByJobButton jobId={jobId} network="basecamp" />
      <VerifyStatusBadge address={status?.address} network="basecamp" />
    </div>
  );
}
```

## What “jobId” unlocks
- Stream live progress and view final state via `GET /api/job/:id/status` and `/logs/stream`.
- Fetch ABIs, sources, scripts via `GET /api/artifacts?jobId=...`.
- Run and read Audit/Compliance (mirrored under the source job):
  - Start with `POST /api/audit/orchestrate` and `POST /api/compliance/orchestrate`.
  - Read with `GET /api/artifacts/audit?jobId=...` and `/api/artifacts/compliance?jobId=...`.
- Verify the deployed contract via `POST /api/verify/byJob`, and show explorer link; poll `/api/verify/status`.

```mermaid
flowchart LR
  A[POST /api/ai/pipeline] -->|jobId| B[GET /api/job/:id/status]
  B --> C[/SSE /api/job/:id/logs/stream/]
  A --> D[Artifacts under tmp/jobs/<jobId>]
  D --> E[GET /api/artifacts?jobId=]
  E --> F[GET /api/artifacts/audit|compliance?jobId=]
  E --> G[GET /api/artifacts/(abis|sources|scripts)?jobId=]
  E --> H[POST /api/verify/byJob] --> I[GET /api/verify/status]
```

Notes
- 202 Accepted: orchestrate endpoints are async; retry fetching reports until available (404 means not ready).
- Network aliases (e.g., `camp` → `basecamp`) are handled on the server.
- Basecamp explorer: `https://basecamp.cloud.blockscout.com/address/<address>#code`.

## Annex A — Frontend‑from‑jobId Reference

Camp_CodeKit is a developer guide and blueprint for generating rich frontends directly from a jobId produced by the backend AI pipeline. It packages clear API usage patterns, React hooks, and UI scaffolding so you can go from “job created” to “interactive UI” rapidly.

This aligns with the existing backend routes in this repository:
- `api/routes/ai.js` — AI generation/fix/pipeline (produces jobId)
- `api/routes/jobs.js` — job status + logs (poll or SSE stream)
- `api/routes/artifacts.js` — sources/ABIs/scripts and persisted audit/compliance reports
- `api/routes/audit.js` — run audit or orchestrate an audit job
- `api/routes/compliance.js` — run compliance or orchestrate a compliance job
- `api/routes/verify.js` — verify contracts by job or address; query explorer status

### Why “frontend from jobId”?
The jobId is the stable handle that ties everything together:
- AI pipeline/fix job produces artifacts, deploys a contract, and stores deploy results under `tmp/jobs/<jobId>/deploy/result.json`.
- Audit/Compliance orchestrate can mirror their reports under the source AI job folder (`tmp/jobs/<AI_JOB_ID>/audit|compliance/report.json`).
- Artifacts reader endpoints prefer job-scoped folders and fall back to project scope.

By centering on jobId, the frontend can:
- stream progress logs; 
- fetch sources/ABIs/scripts;
- read audit/compliance reports once ready;
- trigger and display verification; 
- render interactive views without additional state.

### Quickstart
1) Create a job (example with AI pipeline)
```bash
export BASE_URL="https://<your-api-host>"
curl -s -X POST "$BASE_URL/api/ai/pipeline" \
  -H "Content-Type: application/json" \
  -d '{
    "prompt": "Create a TicTacToe contract...",
    "network": "basecamp",
    "maxIters": 5,
    "filename": "TicTacToe.sol",
    "strictArgs": true
  }' | jq '.job.id'
```

2) Watch progress (poll or SSE)
```bash
# Poll
curl -s "$BASE_URL/api/job/$JOB_ID/status?verbose=1" | jq '.data | {state, step, error}'

# Stream logs (Server-Sent Events)
curl -N "$BASE_URL/api/job/$JOB_ID/logs/stream"
```

3) Fetch artifacts
```bash
curl -s "$BASE_URL/api/artifacts?jobId=$JOB_ID&include=abis" | jq '.'
```

4) Orchestrate audit & compliance and read reports
```bash
# Start orchestrations (they return 202 and a new job id)
AUDIT_JOB=$(curl -s -X POST "$BASE_URL/api/audit/orchestrate" \
  -H "Content-Type: application/json" \
  -d '{ "jobId": "'$JOB_ID'", "fix": false, "deploy": false }' | jq -r '.job.id')

COMP_JOB=$(curl -s -X POST "$BASE_URL/api/compliance/orchestrate" \
  -H "Content-Type: application/json" \
  -d '{ "jobId": "'$JOB_ID'", "fix": false, "deploy": false }' | jq -r '.job.id')

# Wait until completed, then read mirrored reports under the original AI job
curl -s "$BASE_URL/api/artifacts/audit?jobId=$JOB_ID" | jq '.report'
curl -s "$BASE_URL/api/artifacts/compliance?jobId=$JOB_ID" | jq '.report'
```

5) Verify the deployed contract by jobId and check status
```bash
curl -s -X POST "$BASE_URL/api/verify/byJob" \
  -H "Content-Type: application/json" \
  -d '{ "jobId": "'$JOB_ID'", "network": "basecamp" }' | jq '.'

curl -s "$BASE_URL/api/verify/status?address=$ADDRESS&network=basecamp" | jq '.'
```

### Core endpoints (frontend-facing)
- `GET /api/job/:id/status?verbose=1` — job state, steps, result, error
- `GET /api/job/:id/logs/stream` — real-time logs (SSE)
- `GET /api/artifacts?jobId=&include=sources|abis|scripts|all`
- `GET /api/artifacts/audit?jobId=` — persisted/mirrored audit report JSON
- `GET /api/artifacts/compliance?jobId=` — persisted/mirrored compliance report JSON
- `POST /api/audit/orchestrate` — analyze -> optional fix/deploy; mirrors under source job if provided
- `POST /api/compliance/orchestrate` — analyze -> optional fix/deploy; mirrors under source job if provided
- `POST /api/verify/byJob` — verifies the job’s deployed address
- `GET /api/verify/status?address=&network=` — explorer status

### Minimal TypeScript client (pattern)
```ts
export class CampCodeKitClient {
  constructor(public baseUrl: string, public headers: Record<string, string> = {}) {}

  private async json(path: string, init?: RequestInit) {
    const res = await fetch(`${this.baseUrl}${path}`, { ...init, headers: { 'Content-Type': 'application/json', ...this.headers } });
    if (!res.ok) throw new Error(`${res.status} ${res.statusText}`);
    return res.json();
  }

  jobs = {
    status: (id: string, verbose = true) => this.json(`/api/job/${id}/status${verbose ? '?verbose=1' : ''}`),
    logsNDJSON: async function* (id: string) { /* polling fallback if needed */ },
  };

  artifacts = {
    list: (jobId?: string, include: 'all'|'sources'|'abis'|'scripts' = 'all') => this.json(`/api/artifacts${jobId ? `?jobId=${encodeURIComponent(jobId)}&include=${include}`: ''}`),
    audit: (jobId: string) => this.json(`/api/artifacts/audit?jobId=${encodeURIComponent(jobId)}`),
    compliance: (jobId: string) => this.json(`/api/artifacts/compliance?jobId=${encodeURIComponent(jobId)}`),
  };

  audit = { orchestrate: (body: any) => this.json('/api/audit/orchestrate', { method: 'POST', body: JSON.stringify(body) })};
  compliance = { orchestrate: (body: any) => this.json('/api/compliance/orchestrate', { method: 'POST', body: JSON.stringify(body) })};

  verify = {
    byJob: (jobId: string, network = 'basecamp') => this.json('/api/verify/byJob', { method: 'POST', body: JSON.stringify({ jobId, network }) }),
    status: (address: string, network = 'basecamp') => this.json(`/api/verify/status?address=${address}&network=${network}`),
  };
}
```

### React integration (provider + hooks)
Use React Query (or SWR) to simplify state and retries. Example with React Query:
```tsx
import { QueryClient, QueryClientProvider, useQuery } from '@tanstack/react-query';

const qc = new QueryClient();
const api = new CampCodeKitClient(process.env.NEXT_PUBLIC_API_BASE_URL!);

export function AppProviders({ children }: { children: React.ReactNode }) {
  return <QueryClientProvider client={qc}>{children}</QueryClientProvider>;
}

export function useJob(jobId: string) {
  return useQuery({
    queryKey: ['job', jobId],
    queryFn: () => api.jobs.status(jobId, true),
    refetchInterval: (q) => (q.state.data?.data?.state === 'completed' || q.state.data?.data?.state === 'failed') ? false : 1500,
  });
}

export function useArtifacts(jobId?: string) {
  return useQuery({
    queryKey: ['artifacts', jobId],
    queryFn: () => api.artifacts.list(jobId, 'all'),
    enabled: !!jobId,
  });
}

export function useAuditReport(jobId?: string) {
  return useQuery({
    queryKey: ['audit-report', jobId],
    queryFn: () => api.artifacts.audit(jobId!),
    enabled: !!jobId,
    retry: (count, err) => count < 8, // report may not be ready yet
  });
}

export function useComplianceReport(jobId?: string) {
  return useQuery({
    queryKey: ['comp-report', jobId],
    queryFn: () => api.artifacts.compliance(jobId!),
    enabled: !!jobId,
    retry: (count, err) => count < 8,
  });
}
```

### Lifecycle gotchas & best practices
- **202 Accepted**: Orchestrate endpoints are async jobs. Poll or stream until `state === completed` before reading reports.
- **Mirroring**: Audit/Compliance mirror their reports under the source AI job (`tmp/jobs/<AI_JOB_ID>/audit|compliance/report.json`). Frontend should query `/api/artifacts/*?jobId=<AI_JOB_ID>` after orchestrations finish.
- **Retry semantics**: When a report is not ready, `/api/artifacts/audit|compliance` may return 404. Treat as “pending” and retry with backoff.
- **Network aliases**: Verify endpoints normalize `camp` to `basecamp`, etc.
- **Environment**: Ensure `GEMINI_API_KEY` is set on the server for audit/compliance LLM calls; set private keys for networks you deploy/verify on.

### Mapping to server code
- Jobs: `api/routes/jobs.js` and in-memory store `api/lib/jobs.js`
- AI: `api/routes/ai.js` (`/generate`, `/fix`, `/compile`, `/pipeline`)
- Artifacts: `api/routes/artifacts.js` (sources/abis/scripts + audit/compliance readers)
- Audit: `api/routes/audit.js` (analyze, byJob, orchestrate)
- Compliance: `api/routes/compliance.js` (analyze, byJob, orchestrate)
- Verify: `api/routes/verify.js` (byAddress, byJob, status)

  - `GET /api/artifacts/compliance?jobId=` — persisted/mirrored compliance report JSON
- **Audit/Compliance**
  - `POST /api/audit/orchestrate` — analyze -> optional fix/deploy; mirrors under source job if provided
  - `POST /api/compliance/orchestrate` — analyze -> optional fix/deploy; mirrors under source job if provided
- **Verify**
  - `POST /api/verify/byJob` — verifies the job’s deployed address on Blockscout/Etherscan-style explorers
  - `GET /api/verify/status?address=&network=` — explorer status


## Minimal TypeScript client (pattern)
```ts
export class CampCodeKitClient {
  constructor(public baseUrl: string, public headers: Record<string, string> = {}) {}

  private async json(path: string, init?: RequestInit) {
    const res = await fetch(`${this.baseUrl}${path}`, { ...init, headers: { 'Content-Type': 'application/json', ...this.headers } });
    if (!res.ok) throw new Error(`${res.status} ${res.statusText}`);
    return res.json();
  }

  jobs = {
    status: (id: string, verbose = true) => this.json(`/api/job/${id}/status${verbose ? '?verbose=1' : ''}`),
    logsNDJSON: async function* (id: string) { /* polling fallback if needed */ },
  };

  artifacts = {
    list: (jobId?: string, include: 'all'|'sources'|'abis'|'scripts' = 'all') => this.json(`/api/artifacts${jobId ? `?jobId=${encodeURIComponent(jobId)}&include=${include}`: ''}`),
    audit: (jobId: string) => this.json(`/api/artifacts/audit?jobId=${encodeURIComponent(jobId)}`),
    compliance: (jobId: string) => this.json(`/api/artifacts/compliance?jobId=${encodeURIComponent(jobId)}`),
  };

  audit = { orchestrate: (body: any) => this.json('/api/audit/orchestrate', { method: 'POST', body: JSON.stringify(body) })};
  compliance = { orchestrate: (body: any) => this.json('/api/compliance/orchestrate', { method: 'POST', body: JSON.stringify(body) })};

  verify = {
    byJob: (jobId: string, network = 'basecamp') => this.json('/api/verify/byJob', { method: 'POST', body: JSON.stringify({ jobId, network }) }),
    status: (address: string, network = 'basecamp') => this.json(`/api/verify/status?address=${address}&network=${network}`),
  };
}
```


## React integration (provider + hooks)
Use React Query (or SWR) to simplify state and retries. Example with React Query:
```tsx
import { QueryClient, QueryClientProvider, useQuery } from '@tanstack/react-query';

const qc = new QueryClient();
const api = new CampCodeKitClient(process.env.NEXT_PUBLIC_API_BASE_URL!);

export function AppProviders({ children }: { children: React.ReactNode }) {
  return <QueryClientProvider client={qc}>{children}</QueryClientProvider>;
}

export function useJob(jobId: string) {
  return useQuery({
    queryKey: ['job', jobId],
    queryFn: () => api.jobs.status(jobId, true),
    refetchInterval: (q) => (q.state.data?.data?.state === 'completed' || q.state.data?.data?.state === 'failed') ? false : 1500,
  });
}

export function useArtifacts(jobId?: string) {
  return useQuery({
    queryKey: ['artifacts', jobId],
    queryFn: () => api.artifacts.list(jobId, 'all'),
    enabled: !!jobId,
  });
}

export function useAuditReport(jobId?: string) {
  return useQuery({
    queryKey: ['audit-report', jobId],
    queryFn: () => api.artifacts.audit(jobId!),
    enabled: !!jobId,
    retry: (count, err) => count < 8, // report may not be ready yet
  });
}

export function useComplianceReport(jobId?: string) {
  return useQuery({
    queryKey: ['comp-report', jobId],
    queryFn: () => api.artifacts.compliance(jobId!),
    enabled: !!jobId,
    retry: (count, err) => count < 8,
  });
}
```

## Lifecycle gotchas & best practices
- **202 Accepted**: Orchestrate endpoints are async jobs. Poll or stream until `state === completed` before reading reports.
- **Mirroring**: Audit/Compliance mirror their reports under the source AI job (`tmp/jobs/<AI_JOB_ID>/audit|compliance/report.json`). Frontend should query `/api/artifacts/*?jobId=<AI_JOB_ID>` after orchestrations finish.
- **Retry semantics**: When a report is not ready, `/api/artifacts/audit|compliance` may return 404. Treat as “pending” and retry with backoff.
- **Network aliases**: Verify endpoints normalize `camp` to `basecamp`, etc.
- **Environment**: Ensure `GEMINI_API_KEY` is set on the server for audit/compliance LLM calls; set private keys for networks you deploy/verify on.
