# Deployment Guide - Railway + Vercel

Complete guide to deploy WebBuilder with backend on Railway and frontend on Vercel.

## 🎯 Overview

- **Backend (FastAPI)**: Deploy on Railway
- **Frontend (Next.js)**: Deploy on Vercel
- **Database**: PostgreSQL (Railway-provided)

---

## 📋 Prerequisites

### Accounts Needed
- [Railway Account](https://railway.app) - For backend + database
- [Vercel Account](https://vercel.com) - For frontend
- E2B Account - Get API key from [e2b.dev](https://e2b.dev)
- OpenAI/Google API - At least one LLM provider API key

### API Keys Required
- `E2B_API_KEY` - For sandbox execution
- `OPENAI_API_KEY` or `GOOGLE_API_KEY` - For AI agents
- `SECRET_KEY` - Generate with `openssl rand -hex 32`

## 🚂 Part 1: Deploy Backend on Railway

### Step 1: Create New Railway Project

1. Go to [Railway Dashboard](https://railway.app/dashboard)
2. Click **"New Project"**
3. Select **"Deploy from GitHub repo"**
4. Choose your webbuilder repository
5. Railway will auto-detect the Dockerfile

### Step 2: Add PostgreSQL Database

1. In your Railway project, click **"+ New"**
2. Select **"Database"** → **"PostgreSQL"**
3. Railway will automatically create `DATABASE_URL` variable

### Step 3: Configure Environment Variables

In Railway project settings → Variables, add:

```bash
# Database (auto-generated by Railway)
DATABASE_URL=postgresql+asyncpg://postgres:xxx@xxx.railway.app:xxxx/railway

# Authentication
SECRET_KEY=your-secret-key-here-use-openssl-rand-hex-32

# E2B Sandbox
E2B_API_KEY=e2b_xxxxxxxxxxxxxxxxxx

# LLM Providers (at least one required)
OPENAI_API_KEY=sk-proj-xxxxxxxxxxxxxxxx
GOOGLE_API_KEY=AIzaSyAxxxxxxxxxxxxxxxx

# Optional: Anthropic, HuggingFace
ANTHROPIC_API_KEY=sk-ant-xxxxxxxx
HUGGINGFACE_API_KEY=hf_xxxxxxxx

# Vercel Integration (for DApp deployments)
VERCEL_API_TOKEN=your-vercel-token
VERCEL_TEAM_ID=team_xxxxxxxx
```

**Important Notes:**
- Railway automatically sets `PORT` variable - don't override it
- `DATABASE_URL` must use `postgresql+asyncpg://` driver for async SQLAlchemy
- If Railway provides `DATABASE_URL` with `postgresql://`, replace it with `postgresql+asyncpg://`

### Step 4: Deploy Backend

1. Railway will automatically deploy after you push to GitHub
2. Click **"Deploy"** if it doesn't auto-deploy
3. Wait for build to complete (~3-5 minutes)
4. Check logs for any errors

### Step 5: Get Your Backend URL

1. Go to **Settings** → **Networking**
2. Click **"Generate Domain"**
3. Copy the domain (e.g., `evi-web-production.up.railway.app`)
4. **Save this URL** - you'll need it for Vercel setup

### Step 6: Verify Backend Deployment

Test your backend:
```bash
curl https://your-backend.up.railway.app/
```

Should return: `{"message": "WebBuilder API"}`

## ▲ Part 2: Deploy Frontend on Vercel

### Step 1: Prepare Frontend

Make sure you're in the frontend directory:
```bash
cd frontend
```

### Step 2: Install Vercel CLI (Optional)

```bash
npm install -g vercel
```

### Step 3: Deploy to Vercel

#### Option A: Using Vercel Dashboard (Recommended)

1. Go to [Vercel Dashboard](https://vercel.com/dashboard)
2. Click **"Add New Project"**
3. Import your GitHub repository
4. Vercel will auto-detect Next.js
5. Set **Root Directory** to `frontend`
6. Click **"Deploy"**

#### Option B: Using Vercel CLI

```bash
cd frontend
vercel
```

Follow the prompts:
- Link to existing project? **No**
- Project name? **webbuilder-frontend**
- Directory? **./frontend**
- Want to modify settings? **No**

### Step 4: Configure Environment Variables on Vercel

1. Go to **Project Settings** → **Environment Variables**
2. Add the following variables for **Production**:

```bash
NEXT_PUBLIC_API_URL=https://your-backend.up.railway.app
NEXT_PUBLIC_WS_URL=wss://your-backend.up.railway.app
NEXT_PUBLIC_APP_NAME=WebBuilder
```

**Replace** `your-backend.up.railway.app` with your actual Railway domain from Part 1, Step 5.

### Step 5: Redeploy Frontend

After adding environment variables:
1. Go to **Deployments** tab
2. Find the latest deployment
3. Click **"..."** → **"Redeploy"**
4. Wait for deployment to complete

### Step 6: Get Your Frontend URL

Vercel provides:
- **Production URL**: `your-project.vercel.app`
- **Custom Domain**: (optional) configure in Project Settings

## 🔐 Part 3: Update Backend CORS

### Add Your Vercel URL to CORS Origins

The backend is already configured to accept all `*.vercel.app` domains, but you can add your specific domain:

1. Edit `main.py` in your repository
2. Add your Vercel URL to origins list:

```python
origins = [
    "http://localhost:3000",
    "http://localhost:3001",
    "https://webbuilder.elevenai.xyz",
    "https://evi-web-lovat.vercel.app",
    "https://your-project.vercel.app",  # Add your Vercel URL
]
```

3. Commit and push - Railway will auto-deploy

## ✅ Part 4: Verify Full Deployment

### Test Frontend → Backend Connection

1. Visit your Vercel URL
2. Click **"Sign Up"** and create an account
3. Try to create a new project with a prompt like "Build a todo app"
4. You should see real-time progress updates
5. Verify the generated app appears in the preview panel

### Check WebSocket Connection

1. Open browser DevTools → Network tab
2. Filter by "WS" (WebSocket)
3. You should see an active WebSocket connection to your Railway backend

### Test Database

1. Sign up with a new user
2. Refresh the page and log in
3. Your projects should persist (confirms DB is working)

## 🔧 Troubleshooting

### Backend Issues

**Problem**: Database migration errors
```bash
# SSH into Railway container and run manually
alembic upgrade head
```

**Problem**: WebSocket connections failing
- Ensure `NEXT_PUBLIC_WS_URL` uses `wss://` (not `ws://`)
- Check Railway logs for connection errors

**Problem**: CORS errors
- Add your Vercel URL to `origins` list in `main.py`
- Redeploy Railway backend

### Frontend Issues

**Problem**: Can't connect to backend
- Verify `NEXT_PUBLIC_API_URL` is correct
- Check if Railway backend is running
- Test backend URL directly in browser

**Problem**: Environment variables not updating
- Redeploy after changing env vars on Vercel
- Clear Vercel build cache if needed

**Problem**: Build failures
```bash
# Test build locally first
cd frontend
npm install
npm run build
```

### Database Issues

**Problem**: Connection errors
- Verify `DATABASE_URL` uses `postgresql+asyncpg://`
- Check if Railway database is running
- Verify credentials are correct

## 🔄 Continuous Deployment

### Automatic Deployments

Both Railway and Vercel support automatic deployments:

1. **Railway**: Auto-deploys on push to `main` branch
2. **Vercel**: Auto-deploys on push to `main` branch

### Preview Deployments (Vercel)

Vercel creates preview deployments for pull requests:
- Each PR gets a unique URL
- Preview URLs work with Railway backend (regex CORS enabled)

## 🔐 Security Checklist

- [ ] `SECRET_KEY` is randomly generated and secure
- [ ] API keys are set as environment variables (not in code)
- [ ] Database URL uses secure connection
- [ ] CORS origins are properly configured
- [ ] `.env` files are in `.gitignore`
- [ ] Production URLs use HTTPS/WSS

---

## 🚀 Post-Deployment

### Custom Domain (Optional)

#### Railway
1. Go to Settings → Networking
2. Add custom domain
3. Configure DNS records

#### Vercel
1. Go to Settings → Domains
2. Add custom domain
3. Configure DNS records (Vercel provides instructions)

### SSL Certificates

Both Railway and Vercel automatically provision SSL certificates for HTTPS.
